# Notes from agent `opus5a`

Bugs and observations reported during two self-play rounds. Nothing here was
fixed by this agent — per instructions, code bugs were reported, not patched.
Most were fixed upstream by others between rounds; noted where that happened.

## Round 1 — heuristic-guided self-play (300 iterations, default)

- **Unrecognized CLI flags were silently ignored instead of erroring.**
  `cargo run --bin selfplay -- --help` did not print usage — `--help` was
  parsed as an unknown flag, dropped, and a real 200-game run started under
  the `default` tag. The same happened to `train -- --help`, which trained
  from scratch (no `--net-in`) and **overwrote `models/net.bin`**, the shared
  baseline every agent starts from. Recovered via `git checkout` before any
  other agent could pull the corrupted baseline; verified by md5 before and
  after. Fixed upstream in round 2 (`83862a6`): unknown flags now exit(2),
  and `--help`/`-h` print usage and exit before starting anything.

- **`bench`'s `estimated self-play rate` was ~2x optimistic.** It reported
  0.6 games/s; the real heuristic-guided rate measured in production was a
  steady 0.24–0.28 games/s. Worth accounting for when other agents size a
  run off the `bench` number — plan for roughly half its estimate.

## Round 2 — deep-search self-play (1000 iterations, net-guided)

- **`--seed` defaulted to `0` for every agent**, so all parallel agents
  generated byte-identical games regardless of `--tag`. Verified: two
  corpora at 100% overlap. All data generated under this bug was valid but
  worthless beyond one copy. Fixed upstream (`83862a6`): the seed now
  derives from `--tag` unless `--seed` is passed explicitly. Restarted this
  agent's run after pulling the fix; `corpus_overlap` confirmed 0% overlap
  with every other file in `selfplay-data/` afterward.

- **`.gitignore` briefly blocked `.gamelog` output entirely** (`selfplay-data*/`
  matched the whole directory). `git add selfplay-data/<tag>-*.gamelog` was a
  silent no-op under that rule. Fixed upstream (`281d2f2`) to ignore only
  `.shard`/`.bin` inside `selfplay-data*/` and explicitly un-ignore
  `.gamelog`. Confirmed with `git add -n` before pushing.

- **Large, unexplained throughput difference between two runs of the
  identical command** on the same machine: the first attempt measured
  0.06–0.09 games/s; after restarting (same flags, same iteration count,
  same net) it measured a steady 0.23–0.25 games/s from the very first
  checkpoint. No errors or panics in either log. Not confirmed as a code
  bug — the first run overlapped with several `git pull`/`cargo build`/`ls`
  operations competing for the same 4 cores in this session, which is the
  likely explanation, but this was not isolated or verified. Flagging as a
  methodology caveat: don't treat an early rate measurement as reliable if
  other CPU-bound work is running concurrently on the same box.
