# Findings from agent `xdtvd7` (self-play + training runs)

Report-only, per the worker prompts' instructions ("bug → report, don't fix").
No source files were changed. This file documents issues observed across two
rounds of self-play/training so they don't need to be rediscovered.

## Round 1 (300-iteration self-play + train, now fixed/superseded)

1. **`--help` silently ran a full training/self-play pass.** Neither
   `selfplay` nor `train`'s argument parser recognized `--help`; an unknown
   flag was just ignored and the binary ran with default args. Probing
   `train -- --help` overwrote `models/net.bin` (the shared starting point)
   before I noticed and restored it from git. Probing `selfplay -- --help`
   started a real run under tag `default`. Confirmed fixed as of round 2 —
   `--help` now prints usage and exits (verified via `target/release/selfplay
   --help`, exit code 0, no shard written).

   *Update, later in round 2:* re-tested after a fresh build and `--help`
   **still launched a real 200-game run** under tag `default`
   (`selfplay-data/default-*.gamelog`, heuristic-guided, ran until killed).
   So the fix status is inconsistent — possibly only applied to one binary
   (`train`) and not `selfplay`, or reverted. Worth re-checking directly:
   `timeout 5 ./target/release/selfplay --help; echo $?` — a real run prints
   `generating N games on ... -> selfplay-data/...`.

2. **`--seed` defaulted to `0` for every agent**, and the per-game seed was
   derived only from `--seed` and the game index — not from `--tag`. Every
   agent following the documented command verbatim generated byte-identical
   games. I worked around it by passing an explicit distinct `--seed`.
   Reported fixed in round 2: seed is now derived from `--tag` automatically,
   and `corpus_overlap` confirmed 0% overlap between my shard and everyone
   else's without me passing `--seed` by hand.

## Round 2 (1000-iteration deep search self-play)

3. **`.gitignore` blocked the very file the workflow asks you to commit.**
   The blanket rule `selfplay-data*/` also matched `selfplay-data/*.gamelog`,
   so `git add selfplay-data/<TAG>-*.gamelog` silently added nothing and
   `git commit` + `git push` would appear to succeed while pushing an empty
   diff — easy to mistake for "done" with no games actually shared. Fixed
   mid-run with an explicit `!selfplay-data/*.gamelog` negation; verified via
   `git add --dry-run` after the fix.

   Note: `git check-ignore -v` on the fixed repo still reports the file as
   matched by the negation pattern itself and exits 0, which reads as "still
   ignored" if you don't look closely at the shown pattern
   (`!selfplay-data/*.gamelog`, i.e. an unignore rule, not an ignore rule).
   `git add --dry-run` is the reliable check, not `check-ignore`'s exit code.

4. **`git push origin main` silently pushes the wrong ref when not checked
   out on a branch literally named `main`.** My assigned branch is
   `claude/testing-and-running-prompt-xdtvd7`. Repeated `git pull origin
   main` while on that branch fast-forwards *that branch*, but leaves the
   separate local `main` ref untouched at whatever it was when the repo was
   cloned. `git push origin main` then pushes the stale local `main` (which
   was behind), gets rejected as non-fast-forward — which is at least loud —
   but the fix is non-obvious (`git pull` again reports "Already up to
   date" because the *current* branch is up to date, which is misleading).
   The actual fix is `git push origin HEAD:main`. Any agent instructed to
   develop on a differently-named branch but push straight to `main` per a
   worker prompt will hit this.

5. **Throughput note, not a bug:** `cargo run --release --bin bench`
   estimates self-play rate from 8 worlds × 400 iterations. Actual
   `--iterations 1000 --net models/net.bin` self-play measured at **0.06
   games/s** early in the run, later **0.16-0.17 games/s** after the seed-tag
   fix and restart (same 4-core machine, same iteration count — the
   difference is more likely run-to-run variance across kingdoms than the
   fix itself, since the fix only changed seeding, not compute per game).
   Both figures are well below a naive 400→1000 iteration linear scaling of
   `bench`'s heuristic-guided estimate (~0.25 games/s expected). Net-guided
   search at high iteration counts appears markedly more expensive per
   iteration than the heuristic-guided baseline `bench` measures — worth
   accounting for when other agents size a deep-search run against `bench`'s
   number.

6. **Corpus overlap across agents, observed but not mine to fix:** running
   `cargo run --release --example corpus_overlap -- selfplay-data/*.gamelog`
   mid-round showed 100% pairwise overlap between three *other* agents' tags
   (`cwopus`, `deep-verify`, `deep2` — 91-183 shared games each, ~58% of
   total effort duplicated at that point). My own tag (`xdtvd7`) showed 0%
   overlap against every other file both times I checked. Flagging in case
   it indicates some agents were still running pre-fix binaries or reused a
   tag.

## Environment note (unrelated to the above)

A container restart mid-run killed the `selfplay` process outright (no
graceful shutdown, no exit code captured — the harness just reported it
stopped). The incremental-write design meant no data was lost: the
`.gamelog` file was valid up to its last completed game. Restarting picked
up cleanly with a `git pull` + rebuild. Not a code bug, just worth knowing
incremental writes did their job across a harder failure than Ctrl+C.
